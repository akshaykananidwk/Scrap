# ScrapX — Architecture

ScrapX is a B2B scrap trading, buying, selling, RFQ and auction marketplace for India.
It is a dependency-free PHP 8.2+ / MySQL 8 (MariaDB 10.5+) application designed to run on
ordinary Apache shared hosting: upload the files, open `/install`, done. No Composer,
no Node.js, no SSH required for installation or updates.

---

## 1. Runtime requirements

| Requirement | Minimum |
|---|---|
| PHP | 8.2 (tested on 8.4) |
| Extensions | pdo, pdo_mysql, json, mbstring, fileinfo, openssl, curl, gd, zip |
| Database | MySQL 8.0+ / MariaDB 10.5+ (InnoDB, utf8mb4) |
| Web server | Apache with `mod_rewrite` (nginx config documented in INSTALLATION.md) |
| Writable | `storage/`, `uploads/`, project root (for `config.php` during install only) |

## 2. Request lifecycle

```
Browser
  │
  ▼
/.htaccess ──── rewrite everything (except real files) ──► /index.php
  │
  ▼
index.php
  ├─ define ROOT_PATH, load app/Core/bootstrap.php
  ├─ Config::load()          reads /config.php (generated by installer)
  ├─ error/exception handlers → storage/logs/
  ├─ Security headers (CSP, X-Frame-Options, …)
  ├─ Session::start()        hardened cookie params, regeneration
  ├─ Database::connect()     lazy PDO, ERRMODE_EXCEPTION, emulation off
  ├─ Router::dispatch(Request)
  │     ├─ InstallGuard      → /install/* when not installed, 403 after
  │     ├─ MaintenanceMode   → 503 page (admin IP / admin session bypass)
  │     ├─ Middleware chain  (auth, guest, role:*, permission:*, throttle:*, csrf)
  │     └─ Controller@action
  │            ├─ Models / Services (business logic)
  │            └─ View::render() or Response::json()
  ▼
Response (HTML / JSON / file download)
```

Everything is routed through the **project root** `index.php` rather than a `public/`
directory, because shared hosting frequently cannot re-point the document root.
Sensitive directories (`app/`, `config.php`, `storage/`, `database/`, `resources/`) are
denied by `.htaccess` rules, and `uploads/` has its own `.htaccess` that disables PHP
execution entirely.

## 3. Layered design

```
Controllers   thin: validate input → call service/model → render view or JSON
Services      business rules, transactions, side effects (bids, orders, updates…)
Models        one class per table, extends Core\Model (typed CRUD + scopes)
Core          framework primitives, no domain knowledge
Views         plain PHP templates + layouts, all output escaped via e()
```

**Rule:** controllers never contain SQL, models never render, services never `echo`.

### Core primitives (`app/Core`)

| Class | Responsibility |
|---|---|
| `Config` | Loads `/config.php` + database-backed settings cache |
| `Database` | PDO singleton, `select/first/insert/update/delete/count`, transactions, `SELECT … FOR UPDATE` |
| `Model` | Base active-record-lite: fillable, casts, soft deletes, timestamps |
| `Router` | Verb + pattern routing, named routes, route groups, middleware |
| `Request` / `Response` | Input access, files, IP, JSON/redirect/file responses |
| `View` | Template rendering with layouts, sections, partials |
| `Session` | Hardened session, flash messages |
| `Csrf` | Per-session token, `verify()` on every POST |
| `Auth` | Login, logout, hashing, RBAC role/permission checks, API tokens |
| `Validator` | Rule-based validation with Indian formats (GSTIN, PAN, mobile, pincode) |
| `Uploader` | MIME + extension + size validation, random names, EXIF strip, image resize |
| `Crypto` | AES-256-GCM encryption of secrets (GitHub token, SMTP/API credentials) |
| `Logger` | Level-based file logging to `storage/logs/YYYY-MM-DD.log` |
| `Migrator` | Discovers `database/migrations/*.php`, applies pending, records in `migrations` |
| `RateLimiter` | DB-backed throttling for login, OTP, bids, API |
| `Paginator` | Offset pagination + query-string preserving links |
| `Lang` | Translation loader (`en`, `hi`, `gu`) with `__()` helper |

## 4. Domain services (`app/Services`)

| Service | Notes |
|---|---|
| `SettingsService` | DB-driven settings with in-request cache + typed accessors |
| `AuctionService` | Auction lifecycle: open, close, extend, award, expire (cron-safe) |
| `BidService` | **The critical path.** Transaction + `FOR UPDATE` lock on auction row, validates increment/reserve/eligibility/timing, writes bid + audit, applies auto-extension, marks outbid |
| `OfferService` | Offer/counter state machine → creates order on accept |
| `RfqService` | RFQ lifecycle, quote comparison, award |
| `OrderService` | Order creation from any source (auction/offer/fixed/RFQ), status history |
| `WeighmentService` | Expected vs actual weight → recalculated settlement |
| `CommissionService` | Buyer/seller/auction/listing fees from settings → `commissions` rows |
| `WalletService` | **Ledger first**: every balance change is an immutable `wallet_transactions` row; balance is derived and reconciled |
| `InvoiceService` | GST invoice numbering + HTML/PDF-ready rendering |
| `NotificationService` | Event → template → per-channel queue rows |
| `Notifications/*Provider` | `DatabaseProvider`, `MailProvider`, `SmsProvider`, `WhatsAppProvider` implement `ChannelProvider` |
| `Payments/*Gateway` | `ManualGateway` (default), `RazorpayGateway` (enabled by settings) implement `PaymentGateway` |
| `SearchService` | Abstraction over `MysqlSearchDriver` (FULLTEXT + filters); Elastic/Meili drivers can be added |
| `AuditService` | before/after JSON diffs for every significant action |
| `FraudService` | Risk scoring rules → `fraud_flags` |
| `Updates/UpdateService` | GitHub check + apply, backup, migrate, health-check, rollback |
| `BackupService` | ZIP of files + `mysqldump`-free PHP SQL dump, retention policy |
| `HealthService` | Post-update checks: DB, extensions, schema, routes, writable paths |
| `CronService` | Job registry run by system cron **or** web fallback with a secret key |

## 5. Data architecture

- InnoDB, `utf8mb4_unicode_ci`, foreign keys everywhere, `ON DELETE CASCADE` only for
  true child rows (images, history), `RESTRICT`/`SET NULL` for references.
- **All money and weight columns are `DECIMAL`** — never `FLOAT`. Money is `DECIMAL(15,2)`,
  rates `DECIMAL(15,4)`, weights `DECIMAL(15,3)`, percentages `DECIMAL(6,3)`.
- Timestamps stored in **UTC** (`DATETIME`), rendered in `Asia/Kolkata` via `View`/`fmt_dt()`.
- Soft deletes (`deleted_at`) on user-generated content (listings, requirements, messages…).
- Every table has `created_at`; mutable tables have `updated_at`.
- Full schema: [DATABASE_SCHEMA.md](DATABASE_SCHEMA.md).

### Concurrency-sensitive tables

`auctions`, `bids`, `orders`, `wallet_transactions`, `invoices` are only written inside
explicit transactions. Bidding takes `SELECT … FROM auctions WHERE id = ? FOR UPDATE`
so two simultaneous bids cannot both pass the "highest bid" check.

## 6. Security model

| Threat | Control |
|---|---|
| SQL injection | PDO prepared statements only; identifiers whitelisted against column maps |
| XSS | `e()` escaping helper used in every template; `Response::json` sets correct type |
| CSRF | Token in session, `Csrf::verify()` enforced by middleware on all state-changing verbs |
| Session fixation | `session_regenerate_id(true)` on login/privilege change |
| Brute force | `RateLimiter` on login, OTP send/verify, password reset, bidding, API |
| Broken access control | `Auth::can()` + `permission:` middleware + per-record ownership checks in controllers |
| IDOR | Every controller loads records scoped by owner (`forUser()`), admin bypass is explicit |
| Upload abuse | Extension+MIME+magic-byte check, size caps, random names, `uploads/.htaccess` kills PHP |
| Path traversal | All file paths resolved with `realpath()` and confined to a base directory |
| Secret exposure | `Crypto` AES-256-GCM with `app_key`; tokens never rendered, only `••••last4` |
| Clickjacking / MIME sniff | Security headers set centrally in `bootstrap.php` |

Details: [SECURITY.md](SECURITY.md).

## 7. Update system (GitHub-based)

```
Admin → System → Updates
  ├─ Save owner/repo/branch/token  (token encrypted at rest)
  ├─ CHECK FOR UPDATE  → GitHub API: latest commit + version.json + changed files
  └─ UPDATE NOW        → 20-step pipeline:
        preflight → maintenance ON → backup (files+DB) → download zipball →
        verify → extract → diff → apply (skipping protected paths) →
        migrate → clear cache → health check → maintenance OFF → report
        ↳ any failure → automatic rollback (files + DB + version) → report
```

Everything is recorded in `system_updates` / `system_update_files` / `system_backups`.
Details: [UPDATE_SYSTEM.md](UPDATE_SYSTEM.md).

## 8. Extension points (future-ready, not stubs-that-lie)

Each of these is an **interface with a working default implementation**; enabling a richer
provider is a settings change, not a code change:

- `PaymentGateway` — `ManualGateway` works today; `RazorpayGateway` activates when keys are set.
- `ChannelProvider` — database + SMTP work today; SMS/WhatsApp providers log and queue until
  credentials are configured (clearly shown as "not configured" in admin).
- `SearchDriver` — MySQL driver today; Elasticsearch/Meilisearch drivers can be dropped in.
- `GeoProvider` — local pincode/lat-lng tables today; Google/Mapbox adapter later.
- `VerificationProvider` — manual admin KYC today; GST/PAN API adapters later.

Anything not yet implemented is surfaced in the UI as **disabled + configurable**, never as a
dead button. See FEATURES.md for the honest per-feature status table.
